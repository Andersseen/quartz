# STABILITY AUDIT — Core + all existing Primitives (2026-09-02)

> Full audit of Quartz `@quartz-headless/core@0.4.0` + `@quartz-headless/primitives@0.4.0` against
> the architectural rules in `ARCHITECTURE.md`/`BEST_PRACTICES.md`. Goal: consolidate what
> already exists, not grow horizontally. No new primitives, no new Core "manager" foundations.
> Every fix below closes a real bug, a11y gap, headless-policy violation, SSR/lifecycle issue, or
> confirmed DX inconsistency — nothing was changed just because it could be written differently.

Severities: **P0** = correctness / serious accessibility / data-lifecycle failure. **P1** =
important architecture/a11y/DX issue. **P2** = worthwhile improvement. **P3** = future idea/polish.

The most invasive fix in this audit — Tree is the oldest primitive and predates the current strict
headless/Collection/Focus/Dismiss/Directionality conventions.

## Cross-cutting: ID generation / SSR / hydration

**Verdict: SSR/hydration-safe as-is — no confirmed correctness defect.** No `Math.random()`/`Date.now()`
is used for any id anywhere in the library (grep-confirmed clean); the demo app runs SPA-only
(`analog({ ssr: false })` in `vite.config.ts`), so there is no live SSR exposure in this repo today;
and even reasoning through a hypothetical persistent-process SSR consumer, every id-owning element
binds through a live `[attr.id]` binding read by the _same directive instance_ that computes the
paired `aria-controls`/`aria-labelledby`/`aria-describedby`/`aria-activedescendant` — id and reference
are always generated together off the same counter read and can never diverge within one render, and
Angular's hydration reconciles by structural position, not attribute-value equality, so a different
absolute counter number between requests is invisible and harmless. No hardcoded test asserts an exact
`qz-*-N` id string (all assertions are relational). Overlay-portaled content (Dialog/Tooltip/Popover/Menu)
has zero SSR exposure regardless, since it's only constructed on client-side interaction.

checked-in, reviewable fixture — `package.json.template`, `tsconfig.json` matching this repo's own

added to the pre-commit hook — it does a real network-touching install, meaningfully slower than the
filesystem-only `verify:build`.

## Versioning recommendation

This round mixes genuinely compatible bug fixes (Focus, Dismiss, Collection, Overlay stacking,
Toast, Popover/Combobox/Dialog lifecycle, Splitter, Navbar `stuck`, Viewport SSR docs) with
**deliberate, documented, pre-1.0 breaking API cleanups**:

- Tree's custom-template contract (consumers must strip role/tabindex/aria/handlers from their
  own template root)
- Tooltip's `tooltipInteractive` removal (migrate to Popover)
- Controls' `button[...]` selector tightening on Checkbox/Switch/Toggle/ToggleItem
- Switch's `toggled` → `checkedChangeCommitted` rename

None of these breaking changes affect this repo's own demo app or test suite (verified per-area
above), but they are real breaking changes for any external consumer already on 0.4.0. Per the
project's own pre-1.0 policy ("breaking API changes are acceptable but should be deliberate and
documented"), **recommend `0.5.0`, not `0.4.1`**. All breaking changes are itemized above with
their exact migration path; see `CHANGELOG.md`/README for the consumer-facing writeup.
