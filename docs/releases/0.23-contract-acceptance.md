## API snapshot determinism

`checker.typeToString()` can emit equivalent union members in different iteration orders. In the
reported 0.22 drift, Avatar `state` and InputOTP `inputMode` had the same members; only order
changed. The guard now parses the checker text as a TypeScript type and recursively sorts only
union members with a locale-independent comparator. It does not reorder overload signatures,
tuple elements or object members. No declarations were changed to address this drift.

The prior consumer evidence recorded TypeScript `5.9.3`. A controlled checker comparison against the
same built declarations on TypeScript `5.9.2`, `5.9.3` and `6.0.3` produced identical Avatar and
InputOTP strings. Reversed declaration member orders, including a nested `InputSignal` union, also
produced identical checker output in those versions. This does not reproduce a version-specific
change or prove the cause of the specific local/CI environment difference. It does establish the
failure mode: the guard recorded checker text verbatim, so any change in the checker's union member
iteration order became a false API diff. The AST regression tests canonicalize the type text and
continue to detect actual member changes.

The three snapshot files only reorder union members in type strings; export names, kinds, signatures,
Angular metadata and defaults are unchanged. Repeated `node scripts/api-guard.js` checks passed
twice against the unchanged built API.

## Generated playground compilation

The consumer harness reads the registered `DOC_PLAYGROUNDS`, writes the actual generated Component
source into a throwaway Angular app, and compiles the app against installed packed Quartz packages.
It uses Angular AOT, `strictTemplates`, strict TypeScript, and `skipLibCheck: false`; it imports no
workspace library source. Families: Toolbar, ToggleGroup, Toggle, Slider, RangeSlider, Select,
InputOTP, Pagination and NavigationMenu. Variants: default and one representative state per family
(18 total). Negative proof runs in the Angular 21.2 current fixture and checks invalid export,
unknown input, wrong input type, invalid two-way binding and missing state diagnostics.

The passing installed-tarball Angular 21.2 current build was recorded with Angular `21.2.25`,
Angular build `21.2.29`, TypeScript `5.9.3`, and Quartz tarballs at `0.16.0`. It exposed and led to
fixes for duplicate generated class imports and the ToggleGroup committed-output handler type.
All five temporary negative cases failed with the expected compiler diagnostics, then the clean
Angular 21.2 current build passed. The generated hosts are placed in an Angular `@if (false)` block
in the disposable consumer app: the AOT compiler still type-checks every component template, while
the examples do not add duplicate labels or interactive controls to runtime pages. The consumer
Playwright subprocess now receives `CI=1`, matching its configured two-worker CI profile.

All three strict installed-package Angular fixture builds passed: Angular 21.2 minimum (21.2.0),
Angular 21.2 current (21.2.25) and Angular 22 (22.2.4). The current 21.2 consumer run passed all
100 Chromium scenarios and 99 Firefox scenarios (one intentionally skipped OS clipboard scenario).
The external CLI source-copy consumer passed its strict build and browser check in Chromium and
Firefox (2/2).
