## Public contract decisions

| Question                                 | Decision                                                                                          |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Typed `DialogRef` close result           | **No.** Closure state carries results; optional generic with `void` default stays possible later. |
| Close reasons for Dialog/Popover/Menu    | **No.** Nothing observable is lost (`closed$` once); no new exports.                              |
| Dialog accessible name                   | Template context `ariaLabelledBy`/`ariaDescribedBy`, configured ids, or new `ariaLabel`.          |
| Dangling `aria-labelledby`/`describedby` | Never written; unnamed dialog logs a dev-mode warning; no fabricated generic name.                |
| Modal isolation mechanism                | Native `inert` on path siblings (`aria-hidden` fallback), internal and ref-counted per Document.  |
| Toast severity                           | `error` → `alert`; others → `status`; `aria-atomic`; progress `aria-hidden`.                      |
| Toast styling                            | Four consumer CSS variables with previous defaults; no visual design added.                       |
| Tooltip string/template paths            | Same ARIA, timers and dismissal contract; one rendering engine deferred (see limitations).        |

Full rationale: `docs/ai/specs/v1-floating-contract.md` §8–9 and `v1-layer-composition.md` §3.4.

## Modal isolation design

`packages/primitives/src/dialog/modal-isolation.ts` (internal, not exported). On open the dialog
marks as inert every sibling along the path from its backdrop/wrapper to `<html>`, except Quartz
portals (`[data-qz-overlay-container]`, `[data-qz-tooltip]`, `.qz-toast-portal`). Wrappers already
inside the overlay container are isolated individually, wrappers opened later are not. Holds are
ref-counted per element and Document; original `inert`/`aria-hidden` is captured and restored when
the last hold goes. A `MutationObserver` on the path ancestors isolates later siblings and ignores
nodes Angular re-parented before the callback (a real bug found by the E2E run: a nested dialog's
content was becoming inert). Release happens before focus restoration.

## API changes, breaking changes, migration

- Public exports and signatures: **unchanged** (`docs/api/snapshots/` identical; `pnpm verify:build`).
- Additive: `DialogConfig.ariaLabel?: string`; `--qz-toast-*` CSS variables; `data-qz-tooltip` hook.
- Behavioural (pre-1.0, documented in the changelog): Tooltip appends/removes its own
  `aria-describedby` token; Dialog drops unresolved aria references; background of an open modal is
  inert; `<body>`-level portals created by consumers during a modal are background.
- Migration: none required. Dialogs without a title should pass `ariaLabel` (or bind
  `ariaLabelledBy`).

## Accessibility evidence and limits

- `@axe-core/playwright` (WCAG 2 A/AA tags) reports no violations for the open dialog, an open
  menu, an open listbox and a toast. A scanner is a regression net, not certification.
- The scan found one real gap: a `qzSelectListbox` has no accessible name by default. Select's
  control contract belongs to 0.9, so the fixture names it with `aria-label` and the gap is
  recorded below.
- **Manual assistive-technology validation (VoiceOver/NVDA/JAWS) of Toast announcements, dialog
  naming and inert behaviour was NOT performed. It remains pending.**

## Known limitations

- Select listbox has no default accessible name (0.9).
- String tooltips and template tooltips use different rendering paths (shared contract, one
  positioning function, not one engine).
- Consumer portals appended to `<body>` while a modal is open are isolated; there is no opt-in hook.
- While a modal is open, Toast content is clickable but not reachable with Tab (the trap keeps Tab
  in the dialog).
- Popover is non-modal and leaves Tab to the browser; portals render at the end of `<body>`.
