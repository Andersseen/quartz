# Migration notes toward the 0.5 baseline

Status: phase 0.6 documentation. The checkout manifests currently report `0.5.0`, while
`CHANGELOG.md` previously ended at `0.4.0`. This note documents known changes from the audit
without claiming that a registry release exists.

## Button-first controls

Checkbox, Switch and Toggle are button-first primitives. Consumer examples should use button hosts:

```html
<button qzCheckbox [checked]="accepted()">Accept</button>
<button qzSwitch [checked]="enabled()">Notifications</button>
<button qzToggle [pressed]="pressed()">Bold</button>
```

If older code used a generic element or input host, move to the button host before relying on v1
keyboard and ARIA behavior.

## Switch committed output

Switch now follows the same committed-event naming pattern as Checkbox and Toggle:

```html
<button qzSwitch [(checked)]="enabled" (checkedChangeCommitted)="save($event)">
  Notifications
</button>
```

Older examples that listen for `(toggled)` should be updated. Programmatic writes to `checked` do
not represent a user commit.

## Tooltip interactivity

Tooltip is the non-interactive text/help primitive. Interactive floating content should use Popover
or Menu instead of relying on tooltip content remaining hoverable or focusable.

## Tree template context

Tree node templates should use the documented `TreeNodeContext` shape: `$implicit`, `node`,
`level`, `expanded`, `selected`, `disabled`, `loading`, `loadState`, `error` and `retry`.
Consumers should avoid reaching into Tree internals for lazy-loading state.
