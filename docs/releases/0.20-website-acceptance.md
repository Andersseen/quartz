## E2E

First full run (927 tests): 914 passed, 13 failed. Three were genuine defects of this work in tests I had written or renamed copy (a `<main>` locator on Doqs pages, the renamed hero link used by `production-routes.spec.ts`, a half-built `dist` from an aborted run) and were fixed. The remaining failures were timeouts in `waitForLoadState`/`goto` on pages this milestone does not touch (Firefox/WebKit, differing between runs) and passed when rerun in isolation (30/30) and under `--workers=1`; they look like local load flakes. No blanket retries, no skipped engines, no suppressed hydration errors. A final full run with the finished code (`pnpm e2e --workers=2`, 927 tests, three engines) gave 922 passed and 5 failed: one Chromium Toolbar focus case (`navigation.spec.ts:32`) and four WebKit cases that timed out in `goto`/`browserContext.close` (a guide-page axe scan, the Core-entry journey, the desktop current-route check, a forms overlay cycle). None are new behaviour of this milestone; all five passed 45/45 when repeated three times each with one worker. They are recorded here as intermittent local load failures, not as a clean full run. CI (one worker, its own retry policy) is the authoritative result and is recorded in the PR.

New coverage: hero demo pointer + keyboard + ARIA; Preview/Code parity and public-import check; Dialog + Select focus/Escape/axe; install copy success/rejection/unsupported; header current route and mobile menu (closed links unreachable, Escape focus restore, outside dismissal); overflow at 320/375/768/1024/1440; touch targets; prerendered metadata, robots, sitemap; no stale metadata after client navigation; reduced motion; axe in preview/code/dialog/menu/catalogue states; catalogue search/filters/empty/URL round-trip; discovery journey catalogue → docs → demo → API.
