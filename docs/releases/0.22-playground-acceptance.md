## Before / after

Slider with `orientation=vertical`, `disabled`:

```
before: <div qzSlider [(value)]="volume" [min]="0" [max]="100" [step]="5" orientation="vertical" disabled>&lt;div qzSliderTrack&gt;…&lt;button qzSliderThumb aria-label="Volume"&gt;&lt;/button&gt;&lt;/div&gt;</div>
after:
<div
  qzSlider
  [(value)]="volume"
  [min]="0"
  [max]="100"
  [step]="5"
  orientation="vertical"
  disabled
  (valueChangeCommitted)="onVolumeCommitted($event)"
>
  <div qzSliderTrack>
    <div qzSliderRange></div>
    <button qzSliderThumb aria-label="Volume"></button>
  </div>
</div>
```

Affected: Toolbar, ToggleGroup, Slider, RangeSlider (escaped markup); Select, Toggle, InputOTP, Pagination, NavigationMenu (abbreviated `…` snippets, rebuilt on the same serializer). Toolbar additionally ignored its RTL control; it now prints `dir="rtl"`.

## Parity, copy, accessibility

Docs and component pages share the same `DOC_PLAYGROUNDS` entries; the E2E asserts identical text for five families. Copy uses the installed Doqs component (`writeText(snippet.text)`), tested with a stubbed clipboard for success, keyboard activation and rejection. Mobile (375 px) axe and overflow checks pass on the component page. The manual screen-reader gate is untouched and pending.

## Remaining limitations

Snippets are structural (no demo styling). Playgrounds without a `code` option still print none. The Component tabs were reviewed against the public directive sources but are not compiled by a permanent AOT/strictTemplates CI job. Doqs' `<pre>` is not focusable, so code wraps instead of scrolling. Final PR/CI/deployment state is recorded in the PR.
