## Implemented contracts

- Shared calendar state powers the single and range roots; the grid, row, cell, date button and month navigation parts are consumer-owned markup.
- `DatePickerDirective` uses `Date | null`, separate focus and selected models, and the user-only `dateChangeCommitted` output.
- `DateRangePickerDirective` uses ordered `{ start, end }`, publishes the partial start state, previews pointer ranges and rejects spans crossing disabled days or bounds.
- Optional Forms adapters live in `@quartz-headless/primitives/forms`; programmatic writes are silent, and user commits flow once per choice.
- `quartz add date-picker` and `quartz add date-range-picker` copy the shared calendar family without copying Forms adapters.
- Standalone date buttons have a localized full-date accessible name and accept a consumer `dateLabel(date, locale)` override.
- The shared directive contract exposes month navigation, six-week grids, roving focus, keyboard navigation, RTL, locale, grid semantics and styling hooks without shipping calendar CSS.

## Date and timezone decision

JavaScript `Date` is a carrier for a **local civil day**, not an instant. Inputs are interpreted using local year/month/day and normalized to 12:00 local time. Date equality and bounds ignore time-of-day. Constructors use numeric year/month/day arguments; month addition clamps to the final day. Invalid dates normalize to `null`. Noon reduces exposure to DST midnight gaps; this is not arbitrary timezone scheduling.

Local constructors use `setFullYear` after numeric date initialization so years 0–99 are not coerced to 1900–1999 by the JavaScript constructor special case.

SSR/hydration requires a consistent timezone and stable `today` input on server and browser. Different runtime timezones may map the same timestamp to different local civil days. Locale labels use `Intl.DateTimeFormat`; identical text across server and browser requires compatible locale data. No public adapter is exposed because native `Date` is currently the only supported model.

## Migration and release status

This release adds APIs without changing existing exports. Consumers can continue with inline calendar markup and optionally import `DatePickerControlDirective`, `DateRangePickerControlDirective` or `QUARTZ_FORMS` from the Forms secondary entry point. Values use `Date | null` and `{ start, end } | null`; the docs explain the local civil date and partial-range contracts. The CLI registry now supports `quartz add date-picker` and `quartz add date-range-picker`.

The 0.12 manifests target Core and Primitives `0.12.0`, with Primitives peering on Core `^0.12.0`. PR #42 is open; no 0.12 release/deployment workflow has run. The 0.11 failed E2E job retry is in progress. No immutable version was manually published.

## Known limitations and readiness

- Only local civil dates and the Gregorian calendar are supported.
- Month views contain 42 cells, including outside-month days.
- Disabled days can receive keyboard focus but cannot be selected.
- Range completion is rejected if any day in the inclusive span is disabled or outside the inclusive bounds.
- No built-in input, popover or dialog is included.
- 0.11 publication/deployment is a release blocker. 0.12 has passed local checks but is not ready to merge or release until the 0.11 gate and required PR checks pass.
