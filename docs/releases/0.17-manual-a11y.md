# 0.17 manual assistive-technology matrix

**Status: PENDING — no manual assistive-technology evidence has been collected.** The 0.17 roadmap
requires real screen-reader verification in addition to automated tests. The environment that produced
this branch was a non-interactive CLI session (macOS, no one able to operate VoiceOver, NVDA or JAWS), so
**no row below has been executed and none has an outcome**. The automated axe and keyboard assertions in
`consumer/e2e/*.spec.ts` are real but are _not_ a substitute and are not recorded here as passes.

Do not fill the "Actual" and "Outcome" columns from memory or from the automated suite. Run each row,
record what the screen reader announced, and attach evidence (recording, transcript, or screenshot of the
speech viewer). A row that cannot be run keeps `PENDING` and a reason in the last column.

## How to run a row

1. Build and serve the consumer: `pnpm build:lib && node scripts/consumer/run.mjs --fixture angular-21.2 --keep`
   (the runner prints the kept work directory; serve it with `PORT=4300 node serve.mjs dist` from `app/`),
   then open the page named in the row.
2. Start the screen reader, load the page fresh (this also exercises hydration), and follow **Steps**.
3. Compare to **Expected**. Record the exact announcements under **Actual**.
4. Outcome is one of `PASS`, `FAIL`, `PENDING`. A `FAIL` links to an issue.

Record the exact browser and screen-reader versions for every row.
