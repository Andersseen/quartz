## 3. Select labelling contract (replaces the fixture-only workaround)

The popup is named, in order, by: its own `aria-label` / `aria-labelledby` (static **or** bound);
else the trigger's `aria-label`; else the trigger's `aria-labelledby`; else a reference to the trigger
element itself (an id is generated if missing). The attributes are read when the popup opens, so
`[attr.aria-label]` bindings on the trigger work and nothing is overwritten (an early design that
declared them as inputs clobbered consumer attribute bindings and was rejected). `aria-controls`
exists only while the popup exists.

## 4. Angular Forms architecture

Opt-in companion directives in a **secondary entry point** of the existing package; no new npm
package, Core untouched. `@angular/forms` is an **optional** peer (`^21.0.0`). Rationale and per-control
semantics: `docs/ai/specs/v1-forms.md` §3 and §5. `pnpm verify:build` fails if the main entry ever
imports `@angular/forms`, if the optional peer disappears, or if the forms entry bundles the main one.

## 5. Public API changes

- **New entry point** `@quartz-headless/primitives/forms`: `CheckboxControlDirective`,
  `SwitchControlDirective`, `RadioGroupControlDirective`, `SelectControlDirective`,
  `ListboxControlDirective`, `QUARTZ_FORMS` (snapshot `docs/api/snapshots/primitives-forms.json`, 6 exports).
- **Main entry:** export names unchanged (`primitives.json` and `core.json` snapshots identical).
  New members: `valueChangeCommitted` (RadioGroup, Select, Listbox), `touched` (Select), `isDisabled`
  and `setFormDisabled()` (Checkbox, Switch, RadioGroup, Select, Listbox), `SelectDirective.nameListbox()`.
- **Peer dependencies:** `@quartz-headless/core` `^0.9.0`; new **optional** `@angular/forms` `^21.0.0`.
  Consumers that never import `/forms` need nothing new.

### Behavioural changes / breaking changes

| Change                                                                                                       | Who is affected                                                          | Migration                                                                         |
| ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| Removing the checked radio / destroying a RadioGroup no longer sets `value` to `null`                        | Code that relied on the model being cleared                              | Clear the model yourself when you remove the option                               |
| Tabs / Accordion no longer rewrite `value` during teardown; selected-item recovery is applied in a microtask | Code that read the recovered value synchronously after removing the item | Read it after `await fixture.whenStable()` / on the next signal change            |
| Tab `aria-controls` is absent when no panel is rendered                                                      | Styling/tests that relied on the phantom id                              | Render the panel or ignore the attribute                                          |
| `SelectOptionDirective.label` is a function `() => string` (input property renamed `qzSelectOptionLabel`)    | TypeScript code reading `option.label()` as a signal input               | Template `[qzSelectOptionLabel]` is unchanged; `label()` still returns the string |
| Select Tab now moves focus to the trigger before the browser continues                                       | Layouts depending on the previous (broken) order                         | None needed                                                                       |

No export was removed. The CLI (`quartz add`) copies sources from `packages/*/src`; the Forms entry
lives in `packages/primitives/forms` and is **not** available through the CLI — use the npm entry point.

## 7. Accessibility evidence

Automated (axe-core, WCAG 2 A/AA, 2.1 A/AA): the whole `/e2e-forms` form including visible error
messages; the **open Select popup** with no consumer label on the listbox; the 0.8 floating scans
continue to pass with the workaround label removed. Keyboard-only completion of the form in all three
engines and an RTL variant (radio arrows follow reading direction). **Manual screen-reader review was
not performed** (carried to RC). An axe finding about `label-content-name-mismatch` surfaced in the
fixture: a trigger whose `aria-label` omits its visible text violates WCAG 2.5.3 — the supported
pattern is `aria-labelledby="<label-id> <trigger-id>"` (used in the fixture and documented).

## 9. Angular compatibility status

Peers are `^21.0.0`; everything was verified on the repository's Angular 21.2.x only. **Angular 22 is
not verified and not claimed.** Volt requires `^21.2.0 || ^22.0.0`; an Angular 22 fixture and a pinned
21.2 minimum are explicit gates in 0.17 (task 17-09).

## 10. Known limitations and risks

- SSR/hydration is proven by construction (host bindings only, nothing at import) and by AOT compile,
  **not** by a real server render with hydration — 0.17.
- Select shows `displayWith(value)` while closed; the option `label` is for typeahead. A value whose
  option is not rendered is shown through `displayWith` only. Select is single-value (multiple: 0.10).
- Forms + a signal binding on the same model is deterministic but not recommended.
- macOS WebKit does not put plain `<button>`s in the Tab order; the E2E moves between buttons by focus.
- The Forms entry is not distributed by the CLI.
- No manual assistive-technology review yet.
