## 5. Firefox instability (`e2e/docs.spec.ts` "no console errors…")

- Reproduced deterministically: 24 repetitions, 8 workers, Firefox, production build: 21 failed with `ERROR Error` (isolated runs pass).
- Root cause (captured with a console hook): Angular **NG0750** (`@defer` dependency loading failed, no `@error` block). The docs demos use 43 `@defer (on idle)` blocks; when a navigation interrupts an in-flight lazy chunk, Firefox rejects the dynamic import. Classification: documentation-integration defect (missing error handling in the demo registry), exposed by the test navigating away mid-load. Not a library defect.
- Fix: `@error` fallback in all 43 loaders (`src/app/docs-demos/registry.ts`). Regression: `e2e/docs.spec.ts` "a demo chunk that fails to load shows a fallback…" — fails on the old build (all engines), passes after.
- After the fix, `ERROR Error` no longer appears. **A second, different behaviour remains unresolved:** under ≥4 concurrent Firefox workers the same test often hits its timeout because `waitForLoadState('networkidle')` does not settle for 40 s+ with zero pending requests recorded. I could not determine its cause (suspected CPU starvation; not confirmed). I applied `test.slow()` to that one test (20 sequential routes, ~19 s alone) — not a global timeout — which reduced failures from 12/16 to 5/16 at 4 workers; it did not eliminate them.

## 6. Other defect found and fixed

`angular-21.2-min` WebKit: FormField async-validator test missed the 150 ms `data-pending` window (element already `data-invalid` when polled). Test-timing race, not a library defect. Fix: fixture hook `__qzValidatorDelayMs` holds the pending state at 1500 ms for that test. No retries added.
