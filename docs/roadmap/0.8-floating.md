# 0.8.0 — Flotantes y feedback

Estado: propuesta. Entrada: gate Core 0.7. Correspondencia: FLOAT-01…03 y FEED-01.
No incluye selección avanzada, Forms, rediseño visual de documentación ni componentes nuevos.

## Orden

`08-01 → 08-02`; `08-03` y `08-04` consumen Core ya cerrado.
`08-05` tiene contrato propio de feedback. Todos preceden a `08-06 → 08-07`.
Cada tarea se divide si incluye varios comportamientos; ninguna obliga a una reescritura completa.

## 08-01 — Dialog: contrato público y contexto

- **Responsable:** orquestador confirma; implementador ejecuta subencargos aprobados.
- **Archivos:** `dialog.types.ts`, `dialog-ref.ts`, `dialog.service.ts` y specs en
  `packages/primitives/src/dialog/`; snippets de Dialog como consumidor.
- **Decidir antes:** retorno tipado sí/no, estrategia de nombre accesible, referencias ARIA,
  contexto de template y eventos al cerrar. Mantener un solo uso si ese es el contrato elegido.
- **Casos:** configuración mínima accesible, label/description explícitos, contexto genérico
  si se admite, suscripción al cierre antes/después, close repetido.
- **Aceptación:** API y templates compilados coinciden con spec; ARIA referencia elementos
  existentes; no cambiar firmas por comodidad del test.

## 08-02 — Dialog: lifecycle e interacción modal

- **Responsable:** implementador. Depende de 08-01 y coordinación de 0.7.
- **Casos:** sin controles enfocables, Escape, backdrop, programmatic close, destroy del VCR,
  navegación de ruta, opener eliminado y dos dialogs anidados.
- **Aceptación:** cierre exactamente una vez; foco en capa correcta; último modal libera scroll;
  fondo aislado según spec; ausencia de nodos/listeners residuales. Browser obligatorio para Tab.
- **Límite:** si la coordinación Core falla, abrir regresión Core; no duplicar un stack privado
  en Dialog para eludir la foundation.

## 08-03 — Tooltip

- **Responsable:** implementador. Área: `packages/primitives/src/tooltip/` y demo correspondiente.
- **Casos:** hover, focus, blur, Escape, delay de apertura/cierre, trigger destruido antes del
  timeout, cambios de texto, varios triggers, descripción previa del host.
- **Aceptación:** timers cancelados; `aria-describedby` se añade/restaura sin eliminar relaciones
  ajenas; tooltip no recibe contenido interactivo; documentación remite a Popover.
- **Tests:** unidades con fake timers y browser para hover/focus real. No introducir estilos.

## 08-04 — Popover y Menu, encargos separados

- **Responsable:** implementador; asignar `08-04.a` Popover y `08-04.b` Menu, después `.c` submenús.
- **Áreas:** `packages/primitives/src/popover/`, `menu/`; sus contratos y specs existentes.
- **Popover:** controlled open, focus inicial opcional, Escape/outside/Tab según contrato,
  destroy sin haber abierto y destrucción abierto. No emitir closed sin transición.
- **Menu:** Enter/Space/flechas, typeahead, disabled, checkbox/radio items, separadores y foco
  al cerrar. Submenús: dirección RTL, mouse/keyboard, apertura y retorno al item padre.
- **Aceptación:** causa y orden de cierre observables; solo la capa prevista responde; estado
  del item y del grupo consistente. No tratar Popover como modal salvo contrato expreso.

## 08-05 — Toast y anuncios

- **Responsable:** implementador feedback. Área: `packages/primitives/src/toast/`.
- **Separar:** temporización/lifecycle; anuncios/semántica; hooks de contenido/estilo.
- **Casos:** duración cero, varias duraciones, pause/resume si entra en contrato, dismiss,
  destrucción del container, mensajes simultáneos y severidades distintas.
- **Aceptación:** no timer continuo sin toasts temporizados; anuncio por severidad definido;
  close tiene nombre accesible; regiones vacías no interceptan clicks; todo estilo visual
  sigue siendo del consumidor.
- **Revisión:** escáner automático más revisión manual de anuncios en la fase de integración;
  un atributo `aria-live` correcto no prueba por sí solo que el anuncio se escuche.

## 08-06 — E2E de composición

- **Responsable:** integrador/QA; puede asignar un recorrido por encargo.
- **Área:** `e2e/` y hosts de prueba/demo mínimos. Un único escritor en `behavior.spec.ts`.
- **Recorridos:** Dialog→Menu; Dialog→Select; Dialog→Popover; Dialog→Dialog; cerrar/navegar
  mientras el hijo está abierto; dos sistemas independientes en una página.
- **Afirmaciones:** activeElement, capa que permanece abierta, relaciones ARIA, locks del body,
  foco restaurado, ausencia de residuos. No limitarse a contar paneles visibles.
- **Aceptación:** Chromium/Firefox/WebKit. Si Select requiere un cambio propio, crear un
  subencargo específico; no adelantar todo el alcance de selección de 0.9.

## 08-07 — Gate de flotantes

Revisor contrasta API congelada por familia, eventos, temporización y composición. Integrador
ejecuta quality checks, suites pertinentes/completas y regresiones Core. Verificar migraciones
si hubo cambios pre-1.0 aprobados. Ningún workaround del consumidor queda sin documentar.

Salida: superficies flotantes y feedback con contratos cerrados. No arrastrar defectos de foco
o modalización al hito de Forms.
