# 0.23 — Public contract and playground compilation verification

Status: local implementation and verification complete; PR/hosted checks pending. **Not an npm release.** Package versions remain
`0.16.0`. The API remains a freeze candidate and has not been formally frozen.

## Objective

Make declaration snapshots reproducible when TypeScript prints semantically equivalent unions in a
different order, and compile the actual copyable playground Component examples as installed-package
Angular consumers. No new primitive or broad playground redesign is in scope.

## Implementation

- `scripts/api-guard.js` canonicalizes only union member order in checker-rendered type text, using
  locale-independent ordering. It traverses nested type syntax without normalizing overload order,
  tuple order or object member order. Every union member remains represented, so additions and
  removals continue to fail the guard.
- Regression coverage includes representative declarations, nested and literal unions, `null` and
  `undefined`, member additions/removals, public member and Angular input metadata changes, outputs,
  function signatures, overload order, tuple order and public defaults.
- `scripts/consumer/run.mjs` obtains generated code from actual `DOC_PLAYGROUNDS` definitions and
  compiles each family's default and representative non-default Component source in the temporary
  consumer app. The app installs the packed Core and Primitives artifacts and uses its existing
  strict Angular AOT configuration (`strictTemplates`, strict TypeScript, `skipLibCheck: false`).
- The NavigationMenu and Pagination examples now have complete Component tabs; their template and
  component source share the same generators. There are 18 generated Component variants across the
  nine families.
- The Angular 21.2 current fixture injects invalid public imports, Angular inputs, input types,
  two-way bindings and missing state into disposable generated files. Each negative build must
  produce its expected compiler diagnostic; the files are restored before the clean build.
- The current CI consumer-smoke and consumer-matrix jobs already install the release artifacts and
  invoke this runtime harness. Those jobs remain publication dependencies, so a separate release
  workflow is unnecessary.
