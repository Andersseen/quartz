# 0.22 — Playground accuracy, code examples & component developer experience

**An engineering milestone, not an npm release.** `@quartz-headless/core` and `@quartz-headless/primitives` are still `0.16.0`; no `0.22.0` exists or was published. The public API is a freeze candidate (**not frozen**), there is no 1.0 beta, the manual screen-reader matrix is still pending, and 0.17–0.19 still need their formal acceptance. Results: [releases/0.22-playground-acceptance.md](../releases/0.22-playground-acceptance.md).

Starting point: `main` at `ba736b049fc0b5fa68fb82efce52466f7c7eee1c` (PR #56). Branch: `feat/quartz-0.22-playground-dx`.

## Goal

Every playground that prints usage code must print **real Angular template source** that matches the configuration shown in the preview, is identical on `/docs/…` and `/components/:slug`, and copies exactly what is on screen. No new primitives, no library change, no change to the external Doqs package.

## Root cause

`formatDoqUsage(selector, values, { text })` (`@doqs/analog@0.10.0`) is documented as taking _text_: it HTML-escapes `text` (`& < > "`, with `"` restored) and turns `{`/`}` into `&#123;`/`&#125;`. `docs-playgrounds/registry.ts` passed **nested markup** through it (`text: '<div qzSliderTrack>…</div>'`), so the snippet read `&lt;div qzSliderTrack&gt;…`. The playground then prints the string through Angular interpolation into a `<pre><code>`, so the entities were shown literally and copied literally. Nothing is double-escaped _by Doqs_; the contract was misused. The same registry entries feed both the docs page and the component page, so both were affected.

Affected before this change (a snippet containing nested markup via `text`): **Toolbar, ToggleGroup, Slider, RangeSlider** (escaped markup), **Select** (`…` placeholder body). **Toggle** (`text: 'Bold'`) and the one-line template strings of **InputOTP, Pagination** and **NavigationMenu** were not escaped but were abbreviated with `…`; they were rebuilt so every printed family follows one scheme. Playgrounds without a `code` option (Progress, Meter, Avatar, Toast, Listbox, Combobox, Checkbox, Switch, RadioGroup, Tabs, Accordion, Sidebar, DatePicker, DateRangePicker, Drawer, Resizable, Tooltip/Popover arrow) show no usage code and were not touched.

## Decision: a small Quartz-owned serializer, not a Doqs extension point

Doqs offers `DoqPlaygroundCode.code: string | (values) => string` and nothing else for code (verified in the installed types and source: the panel renders `{{ snippet.text }}` in `<pre><code>`, and "Copy" calls `navigator.clipboard.writeText(snippet.text)` — _"Copies exactly the text on screen"_). So the correct layer is the string the function returns, and that string must be Angular template source with exactly one level of escaping.

`src/app/docs-playgrounds/usage.ts` builds it from a tree:

- `el(tag, attributes, children)` — the only way to create markup. A **string child is always text** and is escaped (`& < >`, plus `{ }` → `&#123; &#125;` so Angular does not read them as syntax). Markup cannot be smuggled in through a value.
- `attr(name, value)` — static attribute, value escaped for a double-quoted attribute (`& " <`); a value that Angular would read as an interpolation (`{{ }}`) or that contains control characters becomes a bound string literal, exactly like `formatDoqUsage`.
- `bind(name, value)` — property binding for finite numbers and booleans only; anything else yields no attribute (so `NaN`/`undefined` can never be printed). `twoWay()`, `output()`, `flag()` for `[(x)]`, `(x)` and bare boolean attributes.
- Attribute and element names are validated; an invalid name throws.
- `componentSource()` wraps a template into a standalone component (imports from `@quartz-headless/primitives`, state signals, handlers) so the snippet is **copyable**, not a fragment.

There is no entity _decoding_ anywhere, no `innerHTML`, and `formatDoqUsage` is no longer used by the registry. `usage-code.ts` holds the per-family generators; `registry.ts` only references them.

## Snippet policy

- Each generator shows a **Template (unstyled)** tab and, for the main families, a **Component** tab. "Unstyled" is the honest label: the demo's Tailwind classes and the `--qz-*` positioning styles are presentation, not behaviour, and are omitted. The structure, directives, inputs and outputs are the real ones.
- Printed inputs and outputs are only ones that exist on the public directives (checked against `packages/primitives/src`): e.g. `orientation`, `disabled` (`booleanAttribute`), `allowDeselection`, `minDistance`, `closeOnSelect`, `[(value)]`/`[(values)]`/`[(low)]`/`[(high)]`/`[(pressed)]`/`[(page)]`, `valueChangeCommitted`, `completed`.
- Defaults are omitted (`orientation` horizontal, `disabled` false, `minDistance` 0, navigation delays 150) except where the playground passes the value explicitly and the default is mode-dependent (`[closeOnSelect]` on Select is always printed).
- Pagination lists the first 10 page buttons literally; above that it prefixes an `<!-- Illustrative … -->` comment instead of pretending the fragment is complete.
- Code wraps rather than scrolls (`docs-theme.css`): Doqs' scrollable `<pre>` is not keyboard-focusable and axe flags it (`scrollable-region-focusable`) once snippets got longer than a phone screen. `pre-wrap` keeps the indentation and keeps the copy button in place.

## Tests

- `src/app/docs-playgrounds/usage-code.spec.ts` — serializer unit tests (nested markup, text and attribute escaping without double escaping, injection attempts, interpolation, invalid names/values, wrapping, self-closing components) **and contract tests against the real `DOC_PLAYGROUNDS`** (only the Angular playground _components_ are stubbed): every control of every family with code is toggled and the output is checked for entity leaks, `undefined`/`NaN`, balanced elements, and the expected bindings. Run against the previous `registry.ts` it fails (12 failures), so it guards the regression.
- `e2e/playground-code.spec.ts` — production build, per engine: five families × (docs page, component page) agree and contain real markup; Slider controls change code **and** preview (`aria-orientation`, `aria-valuemax`); Range, Select, Toolbar, ToggleGroup follow their controls; copy writes exactly the visible text (clipboard stubbed, keyboard activation, focus retained); a rejected write reports "Clipboard access is unavailable."; component → docs → component navigation never keeps a stale snippet; no console errors/warnings; mobile axe + no horizontal overflow; checkbox focus preserved while code updates.
- `scripts/release/workflow-gate.spec.mjs` — the release gate: `publish` must `need` quality, package, unit, E2E aggregate, consumer smoke, **consumer matrix and CLI consumer**; its `if` must not contain `always()`/`!cancelled()`/`failure()`; the deep jobs must run on `workflow_dispatch`; the E2E aggregate requires `success`. A skipped dependency leaves `publish` skipped, never run. No workflow change was needed.

## Non-goals kept

No new primitive or input, no library/API change, no Doqs change, no landing/branding change, no API freeze, no publish.

## Remaining limitations

See the acceptance record. In short: snippets are structural (unstyled); playgrounds without a `code` option still print none; Component tabs are not compiled against the public declarations by a permanent CI job; local WebKit cannot launch on the author's host.
