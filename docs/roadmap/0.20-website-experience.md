# 0.20 — Official website, discoverability & interactive developer experience

> **Website engineering milestone. This is NOT an npm release.** "0.20" labels this website work only. No `@quartz-headless/core@0.20.0` or `@quartz-headless/primitives@0.20.0` exists, both manifests are still `0.16.0`, nothing was published, the API is a freeze candidate (not frozen) and no 1.0 beta exists. The 0.17/0.18/0.19 acceptance requirements are unchanged. Evidence: [0.20 website acceptance](../releases/0.20-website-acceptance.md).

Baseline: `main` @ `005aacb4913136a59959dc90e6dfc21e683f08a5` (PR #52). Branch: `feat/quartz-0.20-website-experience`.

## Scope

Improve how developers discover, understand, try and install what Quartz already ships. No new primitives, no library API change, no Doqs or Volt UI change, no new dependency.

## Design notes

- `src/app/site/catalogue.ts` is a projection, not a second inventory: `catalogue.spec.ts` checks each route has a Markdown page, every documented Core/Primitives page is listed, every named export exists in `docs/api/snapshots`, and every export-backed entry has a generated API page.
- `LATEST_NPM_VERSION` (`src/app/site/site-config.ts`) is a constant on purpose; update it only after a real publish (see the runbook).
- A global unlayered `a { color: inherit }` overrode every Tailwind link colour; it is now in `@layer base`.
- Hero/composition demos import only `@quartz-headless/core|primitives` public entry points (asserted in E2E).

## Non-goals kept

No version bump, no publish, no beta, no API freeze, no claim about the manual screen-reader matrix.
