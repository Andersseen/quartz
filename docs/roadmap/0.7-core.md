# 0.7.0 — Core consolidado

Estado: propuesta. Gate de entrada: 0.6. Responsable: orquestador técnico.
Correspondencia: CORE-01…05. No añadir nuevas foundations salvo necesidad aprobada y demostrada.

## Orden y dependencias

`07-01 → 07-02 → 07-03 → 07-04 → 07-08`.
`07-05` (Collection), `07-06` (Viewport/RTL) y `07-07` (Core opcional) se integran antes de 07-08.
El orquestador resuelve los contratos de capas/foco antes de asignar su implementación.

## 07-01 — Clasificar y recuperar foco correctamente

- **Responsable:** implementador Core; revisión técnica obligatoria.
- **Archivos:** `packages/core/src/focus/focus.ts`, `focus.spec.ts`; consumidores en lectura.
- **Subencargos:** (a) foco programático vs tabbable; (b) visibilidad/disabled/inert;
  (c) fallback/restauración. Un modelo recibe solo uno cada vez.
- **Casos:** div sin tabindex, botón normal/disabled, tabindex negativo, ancestro oculto,
  lista de foco vacía, destino eliminado. Especificar qué booleano/elemento se espera en cada
  API; no implementar únicamente una heurística que pase jsdom.
- **Aceptación:** pruebas unitarias del contrato y browser para visibilidad/foco real.
  Conservar firmas salvo modificación ya aprobada en 0.6.

## 07-02 — Diseñar coordinación de capas

- **Responsable:** orquestador; implementador solo reproduce/prototipa si se le asigna.
- **Leer:** `dismiss/dismiss.ts`, `focus/focus.ts`, `scroll-lock/scroll-lock.ts`, OverlayRef y
  DialogService. Revisar cómo se registran portales y traps en Document.
- **Salida propuesta:** spec `v1-layer-composition.md` con propietario de cada evento, capa
  activa, relación modal→portal, aislamiento del fondo y restauración por cierre/destrucción.
- **Casos:** A abierto, B abierto desde A, popup desde B; Escape cierra solo el destino previsto;
  click dentro de portal relacionado no se interpreta como fuera; cerrar B recupera A;
  cerrar A libera el último lock. Dos Documents no comparten estado.
- **Aceptación:** secuencias concretas de foco/capas/locks; estrategia mínima elegida.
  No exigir automáticamente un nuevo LayerManager público ni cambiar todas las APIs.

## 07-03 — Implementar dismiss, locks y coordinación aprobada

- **Responsable:** implementador Core; orquestador revisa composición.
- **Área:** `packages/core/src/dismiss/`, `scroll-lock/`, y solo los puntos de integración
  autorizados en focus/overlay. Si se requiere cambiar Dialog, crear subencargo coordinado.
- **Casos:** destrucción repetida, cierre fuera de orden, evento que abre una capa, Escape
  con controles que gestionan la tecla, popup hijo y locks concurrentes.
- **Aceptación:** una sola reacción por evento; contador/estado restaurado exactamente;
  estilos anteriores recuperados; listeners eliminados. Tests no dependen del orden de ejecución.

## 07-04 — Overlay ante cambios de geometría y lifecycle

- **Responsable:** implementador Core. Depende de 07-02/03.
- **Área:** `overlay-ref.ts`, `overlay.service.ts`, `overlay-trigger.directive.ts`,
  `overlay-position.ts` y specs de `packages/core/src/overlay/`.
- **Dividir:** (a) resize/contenido/ancla según estrategia aprobada; (b) destrucción del host;
  (c) callbacks pendientes/open-close-open; (d) coordenadas y límites de viewport/RTL.
- **Casos:** resize con popup abierto; ancla retirada; navegación que destruye VCR; cierre antes
  de frame/timer; reapertura inmediata; varias instancias; virtual anchor.
- **Aceptación:** posición o cierre coincide con contrato; no wrapper residual ni callback
  tardío que emita/abra después de destroy; E2E geométrico en tres motores.
- **No hacer:** introducir motor de posicionamiento nuevo o nuevas opciones por intuición.

## 07-05 — Collection: orden, recuperación e identidad

- **Responsable:** implementador Core. Área: `packages/core/src/collection/`.
- **Entrada:** contrato aprobado de recuperación; no elegir «primero» o «vecino» sobre la marcha.
- **Casos:** activo eliminado/deshabilitado en sitio, reorder DOM, cero items habilitados,
  registro repetido, typeahead con timeout, loop off, horizontal RTL y cambio de orientación.
- **Aceptación:** `activeId` y `activeItem` no divergen; orden/foco siguen contrato; no mutar
  selección cuando solo cambia foco salvo que el patrón consumidor lo requiera.
- **Regresión:** specs de Listbox/RadioGroup/Tabs que consumen Collection.

## 07-06 — Viewport y Directionality

- **Responsable:** implementador Core. Áreas: `viewport/`, `directionality/`.
- **Casos:** sin window, tamaño inicial, cambio de breakpoint, RTL heredado y local,
  actualización en ejecución, destrucción del injector, dos instancias/documentos.
- **Aceptación:** fallback SSR explícito y estable, cleanup, sin acceso DOM al importar.
  Describir límites de render condicional para la futura fixture SSR; no declarar hidratación
  verificada desde un mock de Document.

## 07-07 — Core condicionado, únicamente si 06-02 lo incluye

- **Responsable:** orquestador asigna una spec por área, no las tres a un modelo.
- **Splitter:** área `splitter/`; min/max, panel retirado, orientación, teclado, pointercancel,
  destroy mid-drag y multitouch/múltiples instancias. Browser para interacción física.
- **Virtual Scroll:** área `virtual-scroll/`; lista vacía/grande, viewport resize, rango,
  actualización de datos, identity/trackBy y cleanup. Explicitar alturas soportadas; no añadir
  variable-height si está fuera de contrato. Browser comprueba elementos y rango real.
- **Drag & Drop:** área `drag-drop/`; acceptance/rejection, reordenación, cancelación, drop
  externo, datos y cleanup. Delimitar soporte input/teclado; no presentar arrastre nativo como
  interacción accesible completa si no la ofrece.
- **Aceptación:** mismo estándar que el núcleo; si no entra, registrar exclusión, no dejar la
  tarea permanentemente «pendiente» dentro del gate obligatorio.

## 07-08 — Gate de Core

Integrador ejecuta tests de Core y consumidores afectados, E2E de foco/geometría/composición,
builds y contract checks. Comprueba umbrales según la subida acordada y matriz de requisitos.
Revisor verifica que no aparecieron exports o dependencies imprevistos.

Salida: contratos Core cerrados y evidencia por requisito. Un riesgo de composición no
resuelto que afecta Dialog/Menu bloquea 0.8; no enviar ese diseño sin resolver a otro modelo.
